## 0. 一句话结论

分层没有「必须推倒重来」的问题，真问题集中在三处：**证据链缺失（CI 绿不等于能工作）、跨层重复实现（同一策略写 3~4 遍）、单文件过载（PlayerActivity 4251 行、handlers_client 1523 行）**。
所以执行顺序必须是 **① 先立门禁 → ② 再删死码 → ③ 再收敛重复 → ④ 最后才拆大文件**。反过来做，就是在没有安全网的情况下搬动 6 万行。

## 3. 真正的重复实现（该收敛 / 不该收敛）

**该收敛**
- 「这条线路是不是 HLS」判了 4 遍：`handlers_client.go:457/976/1199` + `LitvMediaSourceFactory.kt:72`。判据都是 "URL 含 .m3u8"，**HLS 但不带后缀的源会被判成 TS → 黑屏/无声**。应由 Go 算一次 `kind` 下发。
- 信封解包：`Api.kt` 写 3 遍（`:104/:153/:258`）+ `Api.swift:317` 第 4 遍。
- UA 常量 `"LITV/1.0 (Android)"` 6 处硬编码，且已真实漂移（`VlcEngine.kt:433` 兜底成 `"LITV/1.0"`、`MpvEngine.kt:151` 又一份）。
- 引擎选项列表 4 份（`SettingsActivity:54` / `SettingsDialog:36` / `PlayerActivity:2106` / `PhoneHomeActivity:581`），应取 `EngineKind.entries`。
- 「拉全部分页」两套（`LiveView:84-99`、`EpgMappingPanel:118-127`）。
- 源分组排序三实现且语义不同：Go `ORDER BY group_name` / mock `localeCompare` / `clientChannels.ts:125` 按 count 降序。

**不该收敛（保持各端独立）**
- 起播预算 / 看门狗 / 缓冲参数：绑定各端解码器与 Surface 行为，共享常量只会制造假一致。
- `position_sec` 这类字段名：改成 `_ms` 要动 Go+Kotlin+Swift+edge+docs 五处 + 表迁移，不向后兼容 → **明确不做**。

## 6. 本机工具链（已核实，2026-11-23 修订）

**踩到的两个环境坑**：
1. Go 默认 `TEMP=C:\Users\Z\AppData\Local\Temp` **不可写**（`creating work dir: Access is denied`），必须把 `TMP`/`TEMP`/`GOCACHE`/`GOMODCACHE` 指到 `tools\` 下才能编译。
2. `.git/config` 区域的 CRLF 警告是常态（`.gitattributes` 只强制 `.sh` 与 `packaging/fnos/**` 用 LF），提交前按既有纪律做行尾归一化。
