# 00 · 总体方案

> 本文件每个模块的职责都对应源码里的 `// Package` 注释或目录事实，可逐条回溯。
> 代码与本文不一致时，**以代码为准**，并回来修文档——这是本仓库文档失效的主要成因。

## 一、定位

私有部署的 IPTV 源管理与播放平台，跑在飞牛 fnOS 上。

**不提供、不内置、不托管任何直播源。** 所有源由使用者导入，合法性自负。
任何让项目"自带源"的改动都不要做。

## 三、三条主链路

### 1. 请求链路

```
浏览器 → fnOS Unix Socket 网关 → server/api（viaGateway=true，可信 X-Trim-*）
原生客户端 → device bearer token → server/api（viaGateway=false，网关头一律不可信）
```

判定点在 [`Handler(viaGateway bool)`](../../server/internal/api/api.go#L294)。三档认证与 92 条路由的归属见 [01-API](01-API.md)。

### 2. 播放链路

```
上游源 → stream（扇出，多终端共看同台只占 1 份上行）
       → remux（裸 TS → HLS 转封装，不转码）
       → timeshift（边看边录 / 回看）
       → record（录制中心）
       → 终端（Android Media3 / iOS MobileVLCKit / 浏览器）
```

**只转封装不转码**是前提，破了就等于把 NAS 的 CPU 交给直播流。

### 3. 存储链路

SQLite，`modernc.org/sqlite`（纯 Go，**不需要 cgo**，所以 `go test -race` 能跑）。
时间一律 Unix 秒，见 [`store.Now()`](../../server/internal/store/db.go#L361)。

## 四、CI（8 条工作流）

`AGENTS.md §8` 只列了其中 4 条，实际有 8 条——**这是文档漂移，以本表为准**：

| 工作流 | 触发 | 作用 |
|---|---|---|
| `build-check.yml` | push / PR / 手动 | 四 job：preflight、server（gofmt+build+vet+test -race）、admin（typecheck+build）、android（两 flavor 编译+单测+lint 报告） |
| `ios-check.yml` | 仅 `ios/**` 或自身变化 | `test-session`（会话隔离行为测试）+ `build-ios`（编译不签名） |
| `release.yml` | `v*` tag / 手动 | 三端产物（APK / fpk / ipa） |
| `edge-deploy.yml` | 仅 `edge/**` / 每日 / 手动 | 边缘降级：typecheck + 自测 + 部署；Secrets 不全时自动跳过部署 |
| `native-build.yml` | — | 原生库构建 |
| `device-apk.yml` | — | 出设备用 APK（不建 Release） |
| `emulator-build.yml` | — | 模拟器用 x86 包 |
| `readme-downloads.yml` | release published | 同步 README 的 `AUTO:VERSION` / `AUTO:DOWNLOAD` 标记块 |

runner 全部钉版本：`ubuntu-24.04` / `macos-latest`，**不用 larger runner**（按分钟计费）。
