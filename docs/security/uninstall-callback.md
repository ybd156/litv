# fnOS 卸载回调安全规范

## 1. 目标

卸载时允许用户选择保留或删除 LITV 数据，同时确保任何配置错误、路径篡改、符号链接或环境变量异常都不会删除应用边界之外的数据。

## 2. 默认行为

- 默认选项必须是 `keep`。
- `keep` 只能删除 PID、锁文件、看门狗状态和可安全重建的日志。
- 数据库、配置、录制、时移文件、台标和用户媒体目录必须保留。
- 未识别的操作值按 `keep` 处理。

## 3. 允许删除的范围

只有用户明确选择 `delete` 时，才允许清理：

1. fnOS 分配给当前应用的运行时目录。
2. fnOS 分配给当前应用的配置目录。
3. 安装向导保存并经严格验证的 LITV 媒体目录。
4. 目录内由 LITV 创建的数据库、缓存、录制、时移、台标、日志和临时文件。

## 4. 禁止删除的范围

无论任何配置或环境变量如何，都禁止递归删除：

- `/` 及系统目录，如 `/bin`、`/boot`、`/dev`、`/etc`、`/home`、`/lib*`、`/proc`、`/root`、`/run`、`/sbin`、`/sys`、`/tmp`、`/usr`、`/var`。
- 存储卷根目录，如 `/vol1`、`/volume1`、`/mnt/storage`。
- 其他应用、其他用户或共享媒体目录。
- 仅因路径文字包含 `litv` 而被推定属于 LITV 的目录。
- 通过符号链接、`..`、绑定挂载或路径规范化逃逸到允许根之外的目标。

## 5. 路径验证要求

删除前必须执行全部检查，任意一项失败都应跳过删除：

1. 输入非空且为绝对路径。
2. 路径经过 `realpath` 或等价规范化。
3. 规范化结果存在，或其允许父目录和预期目标可被安全确认。
4. 目标不是文件系统根、系统目录或卷根。
5. 目标位于明确的应用所有目录或用户确认的专用 LITV 目录内。
6. 不允许通过字符串包含关系判断所有权，例如 `*litv*` 不能作为唯一依据。
7. 检查目标及关键父级不是指向允许范围外的符号链接。
8. 删除命令必须使用 `--` 终止选项解析，并对路径加引号。

## 6. 推荐的身份标记

用户自定义媒体目录应在创建时写入不可执行的标记文件：

```text
.litv-owned
```

标记至少包含安装实例 ID 和创建时间。卸载时应同时验证：

- 标记存在。
- 安装实例 ID 与当前应用一致。
- 规范化目录在允许的存储卷内。

没有有效标记时，自动清理应拒绝执行并提示用户手工确认。

## 7. 符号链接策略

- 不递归跟随符号链接。
- 应删除应用目录内的链接本身，而不是链接指向的内容。
- fnOS 将应用 `var` 或 `etc` 暴露为链接时，应先验证其规范化目标确实是当前应用的受管目录。
- 无法证明归属时宁可残留数据，也不得扩大删除范围。

## 8. 日志与失败行为

日志必须记录：

- 用户选择 `keep` 或 `delete`。
- 每个清理目标的规范化路径。
- 验证通过、跳过或失败，以及不包含秘密的原因。
- 最终完成状态。

日志不得包含管理员密码、设备 Token、Webhook Token 或完整签名播放地址。

删除失败不得改为尝试父目录，也不得扩大通配符。卸载可以继续，但必须明确记录残留路径。

## 9. 验收测试

至少覆盖以下测试：

| 场景 | 预期结果 |
|---|---|
| 默认卸载 | 保留数据库、配置和媒体数据 |
| 明确选择删除，合法专用目录 | 仅清理该目录和应用受管目录 |
| 目标为 `/`、`/var` 或卷根 | 拒绝删除 |
| 相对路径 | 拒绝删除 |
| 路径包含 `..` | 规范化后重新校验，越界则拒绝 |
| 名称包含 `litv` 的其他用户目录 | 仅凭名称不得删除 |
| 允许目录中的符号链接指向外部 | 不跟随链接删除外部数据 |
| 标记文件缺失或实例 ID 不匹配 | 拒绝自动删除用户目录 |
| 目录名含空格或以 `-` 开头 | 不发生参数注入或误删 |
| 重复执行回调 | 幂等，不扩大删除范围 |

## 10. 当前实现审查结论

`packaging/fnos/cmd/uninstall_callback` 已具备以下正确基础：

- 默认保留数据。
- 对用户媒体目录执行绝对路径、关键目录和深度检查。
- 对应用运行时与配置目录采用清空内容而非直接删除链接。
- 对异常路径采取跳过而不是强制删除。

仍需后续加固：

1. 使用规范化路径而不是仅检查原始字符串。
2. 用受管根目录和所有权标记替代 `*litv*` 字符串判断。
3. 明确处理符号链接和绑定挂载。
4. 为危险路径、越界链接、空格路径和重复执行增加自动化测试。
